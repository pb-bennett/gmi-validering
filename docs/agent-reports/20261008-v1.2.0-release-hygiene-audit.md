### docs/development.md

Correctly separates the active `src/lib/validation-v2/` implementation from the older JSON rules (`docs/development.md:39`–40). The latter should not be interpreted as the active V2 engine. Stats, server-only Supabase/Resend configuration, public CARTO configuration, Kontakt validation/rate limiting, bounded WMS proxy behavior, and production date-setting guidance agree with the inspected source.

The tracking payload is correctly described as the fixed `upload_success` event plus one optional derived coordinate. `FileUpload`, `buildLegacyTrackRequestBody`, and `completeSuccessfulUpload` confirm the richer categorized telemetry is computed but is not sent in the active tracking request. Test-mode suppression is present.

**Minor precision debt:** `docs/development.md:63` permits kommune/fylke/country/unknown aggregation. The current active handler uses the dataset kommune lookup result, or unknown when lookup fails; it does not call the rough Vercel-header location helper. The aggregate model and existing Stats data support broader area categories, but the description could distinguish supported aggregate categories from the active upload fallback. The same paragraph describes one logical kommune lookup; that operation may make an address request followed by a kommuneinfo request for the same coordinate, not multiple coordinates or uploads.

No mandatory pre-release change is needed. Do not change the application to resurrect an old fallback merely to match documentation.

### docs/privacy.md

The principal disclosures match the inspected code: raw measurement files are processed locally; derived coordinates can be used for lookup/terrain; map providers receive map requests; aggregate counts exclude raw file content; Vercel Analytics is mounted; Kontakt sends validated user text through Resend with the server-known app version; optional name/email are stored locally; server secrets and WMS credentials are excluded from persistence.

**Minor precision debt:** `docs/privacy.md:27` and `README.md:49` mention a coarser or unknown area when kommune is unavailable. Unknown is the active fallback today. Narrowing that wording is a small accuracy improvement, not a production blocker or a reason to change tracking behavior. No statement of already-published 1.2.0 or photo integration was found.

### Supporting documentation

`src/features/user-tracking/KOMMUNE-LOOKUP.md:16` explicitly claims fallback to Vercel geo headers, and its troubleshooting text repeats that expectation. This is stale: `createTrackingPostHandler` passes the lookup result directly to `incrementAggregate`; a null location becomes unknown. `getRoughLocationFromRequest` is exported from `location.js` but has no caller in the active route. The lookup code also supports EPSG 4326 in addition to the two UTM codes named in that note. These are harmless internal-documentation debts suitable for a later small correction.

SECURITY remains relevant and makes no outdated release-specific promise. Historical/archive reports are records, not current public feature documentation; older wording there is not a cleanup finding.
