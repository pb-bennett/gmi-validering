# G5 — authoritative field domains and individual editing controls (D1/D2)

Date: 2026-11-12, Europe/Oslo. Branch `feature/photo-workspace`, starting and final HEAD `272082268ee90c599c7a49a2e689dfa979c7e205`. Implementation scope: D1/D2 in [the unified workflow specification](20261111-085500-gmi-validator-rettinger-unified-workflow-planning.md), sections 2.6, 3.7 and 9. D3 and later slices were not implemented.

## Outcome

D1 and D2 are complete. A point's `InnvendigUtvendig` offers ID and OD with their authoritative meanings. Keyboard selection of ID, review, staging and verified download are browser-tested; the downloaded bytes match a source-preserving patch containing exactly `ID`.

The starting HEAD already contained most of D1: `validation-v2/fieldValueDomain.js` derives options from active rules and meanings from authoritative value tables, and `describeGmiEditColumns` in `gmiEditFields.mjs` resolves physical source columns through the existing schema binding, cached by document and geometry. The starting `GmiFieldValueInput` was a basic G4 batch control; the individual editor still used plain text inputs. These implementations were reused rather than introducing another domain/binding mechanism.

## Implementation decisions

### D1 — domains

- Retained the existing pure domain module, active-rule order, geometry-specific options and meanings, comparison metadata, formats and units. No code list was copied or hardcoded into application code.
- Uppercase inference now checks that every option is uppercase-invariant and at least one option contains letters. Numeric lists stay case-neutral, including future lists mixing numeric and alphabetic codes.
- Individual rows obtain their domain from `describeGmiEditColumns`, matched by physical position and source name. `S_FCODE` uses the existing Tema fallback binding. Editability continues to come from the existing individual field policy, independently of batch capabilities.
- Expanded Node coverage checks every enumerated rule's exact ordered code-list equality and derived uppercase flag, authoritative meanings, lone S_FCODE binding in both geometries, domain cache reuse, and original-byte immutability. Existing format/unit and no-duplicate-code-array tests remain passing.

### D2 — controls

- Extended the existing reusable `GmiFieldValueInput` with an explicit `variant="object"`. Its default G4 batch branch and batch call sites retain their previous behaviour; this is not D3 integration.
- Enumerations with at most 12 options use a native select with a blank option and `Annen verdi…`. Custom mode is a text input with `Vis kodeliste`; switching mode alone creates no draft. An out-of-list current value remains its own exact select option.
- Longer lists use an editable ARIA combobox with a labelled listbox, expanded/controls/active-descendant semantics, and options showing code and meaning. Search includes code, meaning and the table's longer description. Arrow keys navigate and scroll the active option, Enter selects its exact code, Escape closes the list, and Tab leaves it. Pointer selection retains input focus. Long lists scroll within a bounded panel in the inspector.
- Only typed drafts are uppercased when the domain calls for it. Mounting, opening a list, choosing an existing option, `Bruk original` and `Angre skrivingen` never trim or recase existing lexemes. Search typing is an editable draft until the user chooses a code; no match is substituted automatically.
- Non-enumerated values retain text inputs, with numeric/decimal input modes and format/unit hints. Date values remain text so accepted source spellings are not converted by a date control. Hints are not validation rules.
- Labels remain associated with the actual input/select. Lexical safety errors retain their existing accessible descriptions and invalid state. Out-of-list values alone are not marked invalid by the control.
- Laptop screenshot review prompted a small control-wrap adjustment so `Bruk original` does not squeeze the select, plus a shorter selected-meaning hint. Longer authoritative meanings remain available in list entries and the hint title.

### D2 — explicit new-FEIL review gate

- Added `gmiEditObjectReviewErrors`, reusing the existing object Validator and diagnostic presentation. It compares the current effective working copy with the correction's actual ChangeSet cell values; skipped requests are not evaluated as edits.
- Previously existing FEIL, resolved FEIL and FEIL already introduced by an earlier staged correction do not demand another confirmation. Newly introduced FEIL, including relationship findings, do.
- Review lists the new reasons and requires `Legg til selv om Validator gir ny FEIL`. Both the stage button and stage handler enforce the checkbox. Approval belongs to that review; going back and building another review resets it. Existing stale-review/session gates remain in place.
- The Validator remains the decision owner. Rules, `fieldPolicy`, `planGmiObjectForm`, M2 ChangeSets, undo/redo, source preservation and export architecture were not changed.
