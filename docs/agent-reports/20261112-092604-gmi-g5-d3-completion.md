## Implementation decisions

- Replaced the basic batch-only input renderer with an adapter to the existing D1/D2 domain control in `GmiFieldValueInput`. The batch-facing `column`, value, callback, label and disabled/invalid semantics remain. A generated id associates `Ny verdi` with its control; the shared combobox retains its listbox, active-descendant and keyboard behaviour.
- The shared control now has optional empty-label/unlisted-hint parameters. Defaults preserve individual editing. Batch uses `Velg verdi…` for its blank offer and suppresses literal out-of-list commentary for numeric-comparison domains. It does not decide numeric validity; the existing Validator does.
- The batch control is keyed by geometry and field so changing fields clears custom/search state along with the existing value reset. It never chooses a field, value or search result automatically. Field-only selection and opening/closing an untouched list do not create a dirty draft or invoke the draft guard.
- Removed strict enumeration membership as a batch input/planner verdict. Safe custom codes from `Annen verdi…` now reach the real Validator and full dry-run; newly introduced FEIL still requires the existing batch risk approval. This deliberately supersedes the former strict-domain Node assertion. Lexical safety checks remain, including semicolon/control-character/encoding safeguards.
- Hydraulic eligibility, numeric lexeme handling and manual applicability rules were not replaced by generic domain logic. UI and Node tests exercise `11`, `11.0` and `11,0` without converting them into a listed alternative. Empty values still cannot be previewed in the UI; no clearing workflow was added.
- The batch adapter spans the existing configuration grid so code meanings and search results have usable width. Its list uses the existing bounded, scrolling shared-control layout.
- Existing modes, preview/invalidation logic, mixed-selection warnings, overwrite/conflict/manual/unvalidated-field gates, dry-run approval tokens, ChangeSets, undo/redo, original source bytes and verified export architecture remain in their existing owners. Validator rules, `fieldPolicy` and domain code lists were not changed. The individual editor itself was not modified.
