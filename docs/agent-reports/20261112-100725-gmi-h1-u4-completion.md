## Outcome and decisions

**H1:** The existing selection reducer now accepts `{ kind: 'rettinger' }` or `{ kind: 'inspection', key }` as its host. Membership, range anchor, geometry, show-only state and provenance are reused only when both source/session binding and host match. An action under another host starts with an empty selection. Inspection keys must be nonempty strings; newly created hosts are immutable snapshots.

The store's existing `changeGmiEditSelection` action takes an optional fourth argument for the host. Its three-argument callers still mean Rettinger. Inspection writes require an open table on the matching layer, matching `selectionContext.key`, matching geometry and the live editable binding. The existing session-store subscription reconciles the selection against that same open inspection. Closing/replacing the inspection, changing key/layer/geometry, hiding or moving the table, replacing the source/session, removing the layer or resetting clears it. Same-field diagnostic replacement and scope/focus view changes preserve it.

Missing hosts retain Rettinger semantics for compatibility with the existing R5 handoff. Its shrink-only provenance lock, exact targets, draft guard, identity verification and explicit conversion remain intact. Existing Node test bodies for Rettinger selection and R5 were retained.

This is host infrastructure only: Validator request construction does not publish selection context yet. The new store tests supply synthetic inspection context directly. No Validator checkboxes, session-opening side effects, map-halo changes or new handoff UI were added; those remain H2/H3 work.

**U4:** A pure helper in `gmiEditView.mjs` supplies visibility, disabled modes/tooltips and the effective view. Ordinary tables hide the entire mode group at zero ChangeSets. In Rettinger, Original stays enabled and Foreslått/Kun endrede stay visible but disabled, with the explanation “Legg til en retting for å vise Foreslått eller Kun endrede.” Exact/contextual inspections retain their existing mode exclusion.

At zero corrections, the table derives Original and does not request a proposed dataset. It never writes back to `gmiEditTableView` or `gmiEditTableViewBy`, so redo restores the stored view and user/auto intent. An explicit Original choice made while empty supersedes the earlier preference. Existing S5 staging intent is unchanged. The existing verified-proposed failure fallback remains in place.

No ChangeSet engine, validation rules, source bytes, fixture hashes, eligibility, approval/export gates, dependencies or G5 value controls were changed.
