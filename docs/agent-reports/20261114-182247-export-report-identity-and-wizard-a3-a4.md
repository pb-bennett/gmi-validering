## 3. A3 — report object identity

**Observed cause:** `deliveryReport` printed `Punkt/Ledning ${sourceIndex + 1}`, which is the array position.

**Change:**

- Each change line is `describeGmiObject(scope, sourceIndex, objectId)` plus ` (GUID …)` when the change carries a GUID. Example: `Punkt 267 (GUID 5ec0…) · Merknad: Punkt 3 → Rettet`.
- Without a GMI number, the existing fallback applies: «Punkt nr. 5 i filen». Without a GUID, the GUID part is left out.
- Fields are split with the existing `isGmiFieldEditReservedColumn`. Changes to `S_HYPERLINK` (and its aliases) go under a separate «Bildelenker endret:» section, printed only when there are any. Ordinary corrections stay under «Feltendringer:».
- The identity comes from fields that already exist: `objectId`/`guid` in the `gmi-only` export summary, and the `diffGmiDatasets` result in `combined`/`split`. The diff engine, `exportGmi`, the patcher and the plan shape are unchanged.

**Tests (Node, synthetic):**

- The fixture has points `:P 101`, `:P 7`, `:P 267` and lines `:L 38`, `:L 43`, so no number equals its position.
- **Kun GMI:** three corrections are reported as Punkt 267, Ledning 38 and Ledning 43, each with its GUID. No line uses a position («Punkt 3», «Ledning 1/2»). No «Bildelenker endret» section.
- **Samlet levering:** with one photo link transferred, there are three field lines and exactly one `S_HYPERLINK` line, under «Bildelenker endret» and after «Feltendringer».
- **Cross-check against the exported bytes:** every change identity is checked against the exported GMI. The test parses `getDeliveryGmiBytes(plan)` with `GMIParser` and compares `id`/`guid` at each `sourceIndex` with the report line. This runs in both modes.
- **Fallback:** a missing number (`null` and `NaN`) gives «nr. N i filen». A missing GUID is left out.

**Plan §8 check (not changed):** the Validator's position-based labels (`validation-v2/diagnostics.js` `affectedObjects.sampleRefs`, `uiIntegration.js` `getValidationV2ObjectLabel`) have no consumer in `src/` outside their own files (grep). I found no path to a user-visible report. This was checked statically, not in the browser.

## 4. A4 — wizard presentation

### 4.1 Kontroll (`data-export-step="review"`)

Kontroll shows, in this order:

1. The status heading.
2. A summary `<dl>`: Leveranse, Rettinger, Bildelenker (kept/transferred), GML, Vedlegg. The filename moved to Pakke; the downloaded report keeps it.
3. One verification sentence, shown only when the delivery is ready.
4. **Må rettes** and **Bør kontrolleres** as open sections, shown without any interaction.
5. **Informasjon (N)** as a closed `<details>`.
6. The experimental Gemini VA note, in one line. It is shown only when the `gemini-g4-unverified` warning is absent, because that warning already says the same thing in Samlet and Delt levering. So it appears in Kun GMI.
7. Photo readiness (`PhotoExportStatus`) and the photo/placement counts line.
8. The excluded-placements note.
9. One closed **Tekniske detaljer** disclosure: format profile and compatibility, unique images and occurrences, and the excluded-asset count.
10. The eksportkontroll disclaimer, once.

### 4.2 Pakke (`data-export-step="package"`)

- The heading «Klar til nedlasting». The done, packaging and failure headings are unchanged.
- One compact line: the filename (`data-export-filename`), then the file count, the photo count and the GML records.
- One status line: «Kontroll fullført · N merknader · Se kontrollen».
  - N counts the «Bør kontrolleres» items plus the photo schema warning, when one is shown in Kontroll. Informational items are not counted.
  - «Se kontrollen» is a link-style button. It dispatches the existing `review` action, so no rebuild happens. It is hidden while packaging.
- The existing `DeliveryInventory`, which still starts collapsed, and the note that the report is not in the ZIP.
- After download, the existing started, SHA-256 and unrecorded messages are unchanged.
- Pakke renders **no** diagnostics, summary `<dl>`, `PhotoExportStatus`, format, counts, experimental note or disclaimer.

### 4.3 Footer, copy and styling

- **One primary action per step:**
  - Innhold: «Kontroller leveransen».
  - Kontroll: «Til pakke».
  - Pakke: «Last ned ZIP» / «Last ned GMI» / «Last ned på nytt».
- **Renamed:** «Last ned leveranserapport» is now «Last ned rapport», as the task asked. The downloaded filename is unchanged (`…-leveranserapport.txt`).
- **Diagnostic panel colours:** the error and warning panels used hex literals. They now use `--gmi-validation-{error,warning}-{bg,border,text}`, following the AGENTS.md status-colour rule for a surface this task owns. **This is a slight shade change:** red-50/200/800 and orange-50/200/800, instead of the old near-equivalent hexes. Warning stays visibly distinct from red (see screenshots).
- **Link style:** «Se kontrollen» uses `--gmi-interactive`, has a `color-mix` hover, the `.gmi-focus-ring` and native button semantics. No new colour tokens were added.
