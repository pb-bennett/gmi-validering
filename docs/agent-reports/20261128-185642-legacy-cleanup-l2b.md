# GMI Validator 2.0 — L2b legacy cleanup completion

## Outcome

Rettinger now uses the table selection and «Rediger valgte (n)» for batch editing. L2b removes the «Masseendringer» footer action, its icon, dialog import and mount, open state and request checks, and the dialog-only CSS. A source search found no remaining `GmiBatchDialog` or `batchOpen` references in `src`. The inspector still uses the shared batch styles and `gmiEditBatchView.mjs`.

The integrated workflow retains table selection, preview, exclusions, manual applicability override, new-FEIL approval, atomic ChangeSet staging, undo/redo, and history. Whole-layer edits start with an explicit selection. The approved parity decision retires «Vis bare objekter med nye FEIL». The existing sortable review column, explicit new-FEIL counts, and approval gate cover review before staging.

### Draft guard

| Dirty drafts | Warning names | Confirmation |
|---|---|---|
| Individual object | «objektet» | «Forkast skjemaet» |
| Batch inspector | «masseendringen» | «Forkast skjemaet» |
| Both | «objektet og masseendringen» | «Forkast begge utkastene» |

The workspace reads `objectDirtyRef` and `batchDirtyRef` when a guarded action is requested. Export, workspace exit, inspector close, and the page guard pass just the action. Cancel preserves the drafts and aborts the action. Confirm invokes the registered batch reset, clears both dirty flags, resets the object form via its existing revision, then runs the action. Where a page action has a separate staged-correction question, it still runs after the draft decision and can still be cancelled. The simultaneous-draft branch was reviewed in code. The ordinary UI switches between the object editor and batch inspector through the guard, and the browser tests exercise each draft separately.
